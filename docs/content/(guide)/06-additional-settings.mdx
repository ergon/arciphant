## Custom base path

If your module/component structure does not start at the root project level, you can specify a base path. For example,
if your application is located in a sub-project `backend`:

```kotlin settings.gradle.kts {2}
arciphant {
    basePath("backend")

    // …
}
```

The base path can also be a nested path (e.g. `backend:my-service` or `backend/my-service`).

In addition to the global base path, every `module`, `library` and `bundle` accepts its own `basePath` parameter. It
_overrides_ the global base path for that module:

```kotlin settings.gradle.kts {4}
arciphant {
    basePath("backend")

    module(name = "reporting", basePath = "backend:services", template = moduleTemplate)
}
```

## Automatic folder creation

By default, Arciphant creates folders for all configured module components if they do not exist yet. You can disable
this behavior:

```kotlin settings.gradle.kts {2}
arciphant {
    disableFolderCreation()

    // …
}
```

:::warning[Gradle >= 9 requires project folders to be present]
Creating folders for each project is especially important for projects using Gradle versions >= 9.
Gradle 9 requires the project folder to be present in order for the project to be configurable (which is necessary for Arciphant to work properly).
If you disable this feature, you are responsible yourself for creating all the necessary folders for your modules and components.
:::

## Qualified archive base name

With Arciphant, a build typically contains multiple Gradle projects with the same name, since all modules have the same
component projects. This can lead to problems when bundling module components together, since the generated jar files of
those components have the same name, too. Without declaring a _duplicate handling strategy_ in the build, this leads to
an error:

```text
Caused by: org.gradle.api.InvalidUserCodeException: Entry BOOT-INF/lib/db-plain.jar is a duplicate but no duplicate handling strategy has been set.
```

To overcome this issue, Arciphant automatically changes the default `archiveBaseName` for task
`org.gradle.jvm.tasks.Jar` to a qualified name `moduleName-componentName` (e.g., in case of a component `domain` of
`module-a`, the resulting base name would be `module-a-domain`).

If you want to _disable_ this feature, you can do so in the Arciphant configuration:

```kotlin settings.gradle.kts {2}
arciphant {
    disableQualifiedArchiveBaseName()

    // …
}
```

This option applies only to `ComponentLayout.PROJECT`. Arciphant rejects it in `SOURCE_SET` mode because that layout
creates a single archive per module.

:::warning[Duplicate name handling strategy required]
Be aware that if you disable it, you have to prevent duplicate names yourself. To solve the issue in a generic way for arbitrary Gradle projects, you can use something like this:

```kotlin build.gradle.kts {2-4}
subprojects {
    tasks.withType<Jar>().configureEach {
        archiveBaseName.set(project.path.removePrefix(":").replace(':', '-'))
    }
}
```

:::
