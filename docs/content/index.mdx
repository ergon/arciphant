## About Arciphant

Arciphant is a Gradle plugin that allows to specify the module structure of complex software project declaratively using
a simple DSL:

- Module templates define the technical structure (components and their dependencies) of modules
- These templates can be configured using a simple DSL directly in the Gradle settings file
- Modules can be instantiated based on templates and further components can be added as required

## The problem

Suppose your application consists of 4 domain modules, each with the same clean-architecture-like structure of 4
components. Mapping this onto a plain Gradle multi-project build means writing 16 `include(...)` statements:

```kotlin settings.gradle.kts
include("module-a:domain")
include("module-a:application")
include("module-a:web")
include("module-a:db")
include("module-b:domain")
// … 8 more include(…) lines for module-b and module-c …
include("module-d:web")
include("module-d:db")
```

…and, more importantly, a `build.gradle.kts` in every one of the 16 component projects, each wiring its dependencies by
hand:

```kotlin module-a/web/build.gradle.kts
dependencies {
    implementation(project(":module-a:application"))
}
```

The architecture rule ("_web_ depends on _application_, which exposes _domain_") is duplicated once per module. It has
to be kept consistent manually, test-fixture dependencies come on top, and every new module means copying the whole
boilerplate again.

## The Arciphant way

With Arciphant, the same structure is declared **once** — as a template in `settings.gradle.kts`:

```kotlin settings.gradle.kts
arciphant {
    val moduleTemplate = template()
        .createComponent(name = "domain")
        .createComponent(name = "application", apiDependencies = setOf("domain"))
        .createComponent(name = "web", dependencies = setOf("application"))
        .createComponent(name = "db", dependencies = setOf("application"))

    module(name = "module-a", template = moduleTemplate)
    module(name = "module-b", template = moduleTemplate)
    module(name = "module-c", template = moduleTemplate)
    module(name = "module-d", template = moduleTemplate)
}
```

Arciphant generates the Gradle projects, wires all component dependencies (including test fixtures) and even creates the
folders on disk — the component projects need no `build.gradle.kts` at all. Adding a fifth module is one line.

This offers various advantages:

- Architecture styles (e.g. Clean Architecture) can be mapped cleanly and declaratively as a Gradle Multi-Project Build
- The boilerplate part in the Gradle code is minimized
- The effort required to introduce a new module is negligible
- No further tools (such as ArchUnit) are required to define the basic architectural units (modules and components) and
  map their dependencies
- Thanks to the interaction with the java-test-fixtures plugin (optional), testing dependencies work out-of-the-box
  without further effort

Arciphant offers the greatest benefit for software projects that consist of many different modules, whereby these
modules have the same or a similar technical structure (e.g. Clean Architecture, Hexagonal Architecture, Onion
Architecture, Layered Architecture) as, for example, in a modulith architecture.

## About the name

The name Arciphant is made up of architecture and elephant, whereby elephant is to be understood as a metaphor for a
large project and at the same time is a reference to the Gradle logo.
